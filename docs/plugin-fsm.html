The plugin as a finite-state machine

GET is an idempotent reconcile. On every controller resync it runs these transitions, so the instance converges to running no matter the apply order.
CREATED
stopped · boot disk detached
▶
boot disk ready → attach
ATTACHED
stopped · boot disk attached
▶
start
RUNNING 🟢
converged — no-op on next GET
↺ disk not ready yet → wait for the next GET     GET fires every resync interval — the state machine re-runs and repairs any drift.
